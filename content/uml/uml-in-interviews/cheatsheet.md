# Cheat sheet: UML in an LLD interview

> [!REMEMBER]
> Sketch in this order: **goals** (use cases) → **classes** → **one flow** (sequence) → **one lifecycle** (state).
> Draw only what answers the question in front of you.

## Draw it when

Always a class diagram; the others when the question leans their way.

## The symbols

| Asked | Draw |
|---|---|
| What, for whom? | Use case |
| Design the classes | Class |
| Walk me through | Sequence |
| What states? | State |
| What's the process? | Activity |
| How deployed? | Component, deployment |

## From C#

Every sequence message is a method; every state event is a method; every class box is a class you will write.

## Mistakes

No diagram at all; five full diagrams and no code; diagrams that disagree.

## Interview one-liners

- "Goals, classes, one flow, one life."
- "Boxes before details."
- "Never skip the class diagram."
